## Production Fix

An actual optimized source compile exposed a query-order bug: the full rustc
`fn_abi_of_instance` query can deduce parameter attributes from `optimized_mir`,
stealing the original producer MIR before the context authenticator borrows it.
The previous scalar-only context fixtures did not expose this aggregate-argument
case. The failing run is retained, not counted as a successful observation.

Capture now checks source signatures/brands and authenticates every original
root's flow before querying full FnAbi for any root. Each MIR borrow ends before
the second loop. The existing full argument/return/layout/calling-convention
checks still run before receipts can leave capture; later import revalidation
still uses those checks. No reduced ABI, optimized-MIR substitute or relaxed
provenance check was introduced.

## Remaining Work

The broader source acceptance test remains present and explicitly ignored as a
known incomplete gate. MIR0 scalar callbacks fail type-layout validation;
O0/MIR2 scalar callbacks fail closure-argument provenance. Review identified two
follow-up hypotheses requiring exact failing-pair/operand confirmation:

- Empty closure and unit may share rustc layout identity but have different
  normalized layout details. Preserve equal-identity/equal-content validation.
- The call graph records closure-typed ZST constant arguments, while closure-use
  observation ignores constants. Authenticate their exact empty environment and
  call/formal correspondence; do not skip unmatched ordinals or invent origins.

Generic callback expansion, scope exit/discharge, independent correspondence,

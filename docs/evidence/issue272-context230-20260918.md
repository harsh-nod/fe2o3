## Implementation

Successful consumption of the authenticated issuer and helper occurrences now
creates a private move-only receipt. Expected helper operands come from retained
rustc MIR and canonical local/type mappings, not the emitted semantic body.
Only the authenticated context argument can recover an erased ZST as a move;
ordinary ZST arguments and surviving Copy/Move operands remain unchanged.

Attachment checks root identity and both typed call boundaries before publishing
anything into the reusable request owner. Sealing checks the complete issuance
roster, root/helper/issuer/type identities, operands and call boundaries against
the admitted source. Private production bindings carry the receipt beside the
existing MIR/SSA owners and recheck its exact source identity after SSA creation.
Operand retention, vector growth and scans share the existing cumulative work
budget. This is bounded logical payload/work, not rustc-query or process RSS
accounting. Root membership uses a prepaid scan; the issuance roster uses a
linear function/block scan and sorted receipt cursor.

These records do not grant callback, scope, graph, artifact or execution
authority. They have no public constructor, decoder or cloning API. The V29
executable materialization refusal remains unchanged.

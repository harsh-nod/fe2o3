# Basic assembly kernel M2 acceptance

On 2026-10-01, the primary integrator accepted M2 for the existing bounded
gfx942 V17 and V20 profiles and typed Rust source-materialization path. The
accepted exits are **M1/M2/V1/V2/U1/U2/U3, seven of eighteen**. All three
umbrella issues remain open.

This is an explicit integration decision against the literal M2 exit in
[#280](https://github.com/harsh-nod/fe2o3/issues/280), not acceptance attributed
to other owners. It credits retained, separately identified evidence; it is
not a fresh execution campaign or acceptance by test count alone. The
[clause and identity record](basic-assembly-m2-acceptance-20261001.json)
preserves the supporting receipt and audit hashes.

## Accepted scope

The whole-entry profile is the checked gfx942 V20 integer path, with launch
64, maximum grid 2, and the supported one-block and four-block kernels. The
mixed profile is the constrained V17 region inside ordinary Rust and LLVM
computation. Source promotion and re-admission retain their existing bounded
helper, specialization, boundary and resource requirements.

| M2 exit clause | Credited evidence | Boundary |
| --- | --- | --- |
| Whole bounded assembly kernel | Authentic one-block, diamond and register-edited source fixtures reach checked KIR V20 and the normal LLVM and inert worker handoff. | Closed integer and launch profiles, not arbitrary physical assembly. |
| Mixed Rust and assembly kernel | The V17 region uses typed integer operations, fixed inputs, early-clobber outputs and explicit scratch clobbers inside ordinary computation. | Existing constrained boundary, not arbitrary helper ABI or control flow. |
| Actual Rust materialization and normal frontend re-entry | The accepted U2 source-promotion chains create Rust source, derive a fresh invocation, and establish new source, canonical and analysis bindings. | One supported region is sufficient for this M2 clause; the full interactive workflow remains U2. |
| Stale source, invalid resource and boundary clobber negatives | U2 retains stale-source and old-roster refusals, unsupported extraction and invalid physical-role or boundary cases. V20 adds wrong launch, foreign input, undefined merge, missing wait, wrong carry, ABI and resource refusals. | Exact supported cases, not a general hazard or hidden-state model. |
| No alternate artifact path | Original consuming compiler owners feed normal checked emission and worker preparation. The independent machine-code observer uses the ordinary worker request path. | Diagnostic code-object observation supplies no protected artifact or launch authority. |

The supporting current-source review and historical records cover 24 checked
source sessions and 576 CPU comparisons, with 15 source refusals, 54 ABI
negative cases and 12 resource denials. A separate six-run O0/O3 machine-code
inspection matrix records 246 native-code inspection refusals, 66 sidecar
refusals and 12 input refusals. “Native” here means emitted code inspection,
not GPU execution.

## Source and machine evidence remain distinct

The historical machine-code matrix joins its own source, canonical identity,
canonical-byte hash, sidecar and LLVM bytes. The later checked source run has
different canonical identities and canonical bytes. Its LLVM bytes match the
historical matrix for each of the three variants; this byte equality does not
make the two canonical owners identical.

The inspection checks the authored entry, branch targets, operands, effects,
descriptor and metadata, including six explicit and thirteen hidden arguments.
The worker identity fields in that diagnostic route are explicitly synthetic.
They do not satisfy a protected finalizer, runtime ABI discharge or machine
refinement obligation.

The [checked V20 route](../physical-entry-checked-v20.md), its
[source qualification](../physical-entry-source-qualification-20260924.md),
and the [U2 acceptance ledger](source-proof-freshness-u2-20260923.md)
retain the implementation and qualification details. Original instruction and
register source remains compiler authority; reports and hash equality cannot
create a source-owned capability.

## Remaining obligations

M3, M4 and M6 remain open, including their applicable memory, synchronization,
second-target, matrix, protected-production, hardware and curriculum criteria.
This decision does not close normal BF16 admission, complete original-recipe
memory accounting, a physical debugger capture, or broader performance budgets.
Kernarg immutability, the 512-byte output envelope and output/kernarg disjointness
remain explicit premises of the bounded whole-entry profile.

The historical outer records do not claim complete descendant quiescence or
transitive build attestation. Their successful observations are retained as
historical evidence. Before a fresh run under the current process-custody policy,
the legacy checked-entry script needs its detached child-group and bounded
close/drain handling corrected. This ledger is not an instruction to rerun that
script unchanged.

Older dated sections that report six accepted exits remain accurate historical
records. They are not rewritten by this decision.

## Scalar Operand Invariant

The existing shared emitter consumes exact retained operand roles for unary,
binary, checked-binary and cast operations, switch discriminants, Assume, and
assert conditions/messages. This permits scalar fields of nominal execution
roots without losing the ordered source-event contract introduced in source239.

- Original source site, operand pointer/role, SSA transition, instance, archive
  and cumulative-ledger checks remain mandatory. No operand role is guessed
  from its value or reconstructed by a second evaluator.
- Reading a scalar sibling does not restore a moved capability. Copying an
  owned capability field or using a moved/stale nominal binding still rejects.
- Folded assert conditions and discarded panic payloads retain source move
  effects. Only logical scalar field projections are consumed; dereferences,
  indexes, memory projections and nominal payloads reject. No discarded
  diagnostic causes a physical load or gains a nominal capability consumer.
- Every required event must be consumed before the outgoing edge. Assert
  projection work uses the existing shared ledger and structural limit.
- Ordinary-only lowering is unchanged. UncheckedBinary's synthetic operand
  path remains unsupported for nominal roots; stores, atomics and nominal
  returns gain no new admission from this change.

New tests cover values/types and checked-overflow flags, switch/Assume, folded
and runtime asserts, ordered one/two-operand diagnostics, moved siblings,
individually omitted source events, owned copies, missing/stale archives, and
exact/one-short work and peak-storage limits. Positive fixtures use admitted
inert owners and test-only seeds, not authenticated rustc capability issuance.

## Implementation

The private move-only source receipts now expose immutable root anchors through
`visit_root_anchors_v29`. It validates source identity and prepays enumeration
before any consumer runs. Consumers receive the same canonical work/storage
ledger; a failure does not reset accounting or roll back caller side effects.
No source clone, allocation, public receipt constructor or decoder was added.

Immediately before pre-ranked materialization, the production pipeline projects
retained identities, both typed call boundaries and expected helper operands into
the lowerer's shared `with_checked_context_root_v29` API. Expected operands come
from the original receipt, not the candidate. The shared checker joins the actual
source calls, SSA plans and source-launch roster. Projection and checking use the
same cumulative budget. The provisional duplicate backend checker was removed.

The lowerer's public input remains untrusted data. Its scoped borrowed view
establishes consistency, not originating source authentication or new authority.
Private production bindings retain the source receipt. Root lookup remains
O(context entries times roots), with each scanned root charged before comparison;
checking allocates no storage. Launch grid custody still comes from the existing
launch contract, not an independent semantic-MIR copy.

The connected consumer currently checks root agreement only. It does not expand
callbacks. The existing V29 executable materialization refusal is unchanged.

## Remaining Integration

Derive callback, borrow, capture, result and continuation relationships from the
existing immutable semantic owner. Neither review found a concrete information
gap requiring another raw-MIR parser or receipt. Generic call transport exists,
but emits retained calls, not expanded callback control flow. Expansion must use
root/invocation-path/derive-occurrence identities, preserve all return transport,
close scopes at complete invocation exits and independently replay these facts.

non-unit/parts results. Existing execution operations, ScopeEnd, memory effects
and same-function lifecycle checks are reusable; new opcodes are not justified
by this checkpoint. Scalarization correspondence, actual callback/output CPU
comparison, protected proof, final artifact admission and safe GPU launch remain
required. No milestone is closed.

## Production Change

Candidate A instrumented actual production type construction. All sixteen MIR0
failures exposed the same mismatch: unit and a capture-free closure shared the
rustc physical layout and therefore the old semantic layout identity. Their
semantic records differed: unit had `details: None`, while the closure had an
empty aggregate detail record. The global equal-identity/equal-content validator
correctly rejected those records. The diagnostic instrumentation was removed.

The producer now hashes the existing normalized-type/physical-layout commitment
together with the authenticated target identity under `semantic-layout/v2`.
There is no new serializer, wire schema, public authority, workload dispatch or
relaxed validator. FnAbi and physical ABI identity domains remain unchanged.
Newly produced semantic layout identities and their dependent source/preflight
commitments change; dependent receipts must be regenerated. Existing valid
frozen semantic documents are not rewritten.

Live rustc tests check the unit/empty-closure collision, distinct nominal closure
types, repeated normalization, target substitution and the framed v2 preimage.
The normalization assertion checks idempotence, not distinct source spellings.
A custody regression changes only a layout identity in an otherwise admitted
source and requires rejection before any consumer callback. Existing incompatible
layout, ABI-adjustment, serialization and adversarial model tests remain strict.
Two native read-only workers reviewed layout custody and the separate remaining
closure-constant work; the primary owned all edits and validation. No Qwen was used.

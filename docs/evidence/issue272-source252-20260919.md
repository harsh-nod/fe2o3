# Source252: Reference Signature and Same-Session Custody

Status: implementation under validation. This is not milestone completion,
native replay, a semantic-equivalence proof, or a kernel qualification result.
All whole #272 milestones remain open; the end-to-end qualified count is unchanged.

## Purpose

The production importer previously cloned the collector's reference binding.
This change retains the live kernel and reference instances, exact instantiated
Rust signatures, registration identity, and ordered function occurrence. Import
re-extracts the binding from those compiler inputs and compares the complete
result before handing it to the existing production path.

The logical signature projection preserves scalar tags (including `usize` versus
`u64` and `isize` versus `i64`), ordered kernel arguments and leading point
coordinates, reference mutability, scalar/slice shape, represented regions, and
authenticated nominal output-carrier distinctions. Its borrowed relation view
does not allocate another mapping. It is descriptive data, not provider authority.
The existing effect-IR digest format is unchanged.

The projection is intentionally not a complete Rust signature. Kernel return
types and output-carrier index-space arguments remain in the retained raw rustc
signature and instance. Only erased/static regions and the existing semantic
argument-count bound are represented; unsupported inputs fail closed.

## Production Boundary

The importer rejects missing, extra, reordered, changed-role, substituted-instance,
changed-name, changed-signature, and changed-binding inputs. Comparison covers
both complete effect trees, helper identities/operands/summaries, predicates,
loop summaries, and the separately retained observable-output lists. Equality
does not rely solely on cached digests.

Initial extraction, capture, replay, and comparison use the existing cumulative
source-work budget, which continues into source preflight. New allocation debits
describe requested logical payload and copying work. They are not a canonical
live/peak-storage receipt, a physical allocator/RSS bound, or a bound on rustc
query internals. Existing local expression and symbolic limits remain relevant.

The raw-source census checks borrowed HIR/MIR/type records before the existing
identity hashes. It does not bound provider authentication, interning, opaque
identity lookups, referenced allocations, diagnostic formatting, or internal
hashing instructions. Its depth limit is 256; coroutine/coverage metadata, MIR
inline assembly and pattern types are refused rather than traversed without
accounting. These are explicit admission restrictions, not new supported syntax.

Bounded loop extraction uses the inherited ledger too. State copies, map keys,
predicates, CFG/dominator work, summaries and recursive constant folding are
charged before the corresponding work. The constant-folder checks the complete
expression tree even when evaluation would short-circuit. Conservative charging
can reject an input earlier under the unchanged work cap. Ordinary opt0 `while`
MIR may contain unused `!` locals: their declarations are admitted, but executable
place access to those uninhabited values remains rejected.

This does not transport a complete CPU/helper source closure to the independent
native checker. A helper summary and body digest are not the missing helper
body/instance preimage. No V6/V2 wire, new proof authority, old clean-report
conversion, policy activation, finalizer, or generated-host contract is added.
The conditional-stage and independent-replay integrations remain separate work.

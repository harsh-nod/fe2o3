## Implemented Boundary

`ProductionPlironSessionV1::prepare_conditional_ranked_analysis_v1` consumes
the genuine constructed session and handles. The pending result owns that
session, exact root/snapshot, structural identity, mutation epoch, selected
requests, complete original ownership report, mandatory bounds failure, every
residual row and the existing analysis manager. There is no context/pointer
accessor, mutable callback, session recovery, clone or clean-input conversion.
All complete-pipeline checks remain explicitly pending.

Contract materialization records the actual emitted operation and view for each
recipe occurrence. A recipe ordinal is not a PLIRON operation ordinal: prior
semantic operations can expand. Preparation validates the complete ordered
operation/view roster, including unselected contracts, and checks the mutation
epoch and genuine graph snapshot. An identical printed replacement is not an
acceptable occurrence substitution. Public diagnostic rows expose no arena
pointer, including through Debug.

The session accumulates capture scan/storage reservations across roots. Both
the old clean verifier route and the pending route reserve this prefix once.
Old pipeline receipts keep their original framing and comparison semantics.
Pending setup prepays selected-row scratch and owner storage before structural
capture, inherits those reservations into the manager, and refuses unexpected
vector capacity. Cache/storage reservations remain conservative; no refund is
claimed while their owners remain live. Existing reports, findings and static
proof counters are preserved rather than filtered or converted into authority.

## Resource Limits

The analysis envelope is not a bound on every constructor operation or process
allocation. Existing graph-snapshot printing and exact recipe rehashing remain
outside it, as do preexisting session arena/recipe allocations. A bounded output
writer alone would not close the printer gap: the pinned printer also creates
temporary argument strings and clones attributes before writing. Those paths
need separately coordinated, incrementally charged traversal and scratch bounds.
No complete-constructor, allocator/RSS or whole-compiler resource proof is claimed.

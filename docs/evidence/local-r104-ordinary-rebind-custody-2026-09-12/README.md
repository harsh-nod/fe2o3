## Source Scope

The ordinary live-rebind entry roots original programs, packets and data before
preflight. It places preparation directly in that root before opening the
existing model loan. The loan callback returns only a result, not an owning
dispatch value. Completed preparation remains rooted through retake and full
live dispatch-memory validation; dispatch installation and detached-ledger
clearing occur only after successful settlement and checked extraction.

Failed calls retain their input root. Healthy preflight rejection and rejection
of an already terminal/attached session do not newly transport or poison the
parent. Existing terminal metadata errors and admitted ordinary failures retain
the original parent as well. Returned errors preserve their prior local
classification; the common loan and pristine helpers retain their existing
process-poison policy, while the outer catch process-poisons unwinds.

The direct wrapper retains the parent before returning or resuming a panic.
The lane facade records a monotonic transport request first. Its outer callback
restores the primary/auxiliary slots, applies callback-panic poisoning, then
retains the complete original parent and leaves an inert terminal shell. A
callback that consumes an error or catches a panic cannot clear that request.
No public method signature, queue engine, memory trait or backend choice changes.

Ordinary detached-generation preparation remains distinct from recycled queue
replacement and pristine continuation authority. The helper accepts zero as
before; the tests do not claim that a real detach produces zero. Incomplete or
failed preparation cannot be extracted even if an injected caller suppresses
its error and validation callback.

Oracles retain exact original packet/data descriptors, backing storage,
program identities, detached ledgers, generation and owner partitions. They
check original account charges/data bytes, no GPU unmap/FREE/VA release,
phase-dependent exact loan/retake counts, actual certified-foundation placement,
stage-specific quarantine, error/panic precedence and checked final installation. Facade
oracles distinguish actual poison state from the release error also returned
by a probe-active completion owner.

Preflight rejection enters neither loan nor retake; rejected opening cannot
perform retake. Successful opening permits exactly one retake, including when
the preparation operation panics.

## Scope Limits

Preparation uses one original memory fixture, its accounts and certified
foundation, real loan/reclaim helpers, and the real memory validation method.
Native leaves remain fixtures. The facade separately has `engine=None`; these
tests do not establish that a live terminal parent contains that external
memory/foundation. The source-routing guard checks production calls, not
native execution or executable refinement.

The 31-stage sweep is not a new lower-level allocation/map/projection fault
campaign. Predecessors are synthetic; native detach, destruction/recreation,
generation succession, later auxiliary vector slots beyond the first, and
physical device behavior are not qualified here. Retained envelopes still borrow caller module
bytes. Allocator abort and panic-abort are not unwind recovery.

Pristine preparation still consumes its existing continuation/helper; its
unreturned internal prefixes remain N2 work. Insertion, release/teardown,
DATA-ADOPT, ISSUE, generated completion, Context versions, aggregate memory
closure and A3-A7 remain separate packets. No new solver result, production
Rust-to-proof correspondence, live KFD run or HIP/HSA performance claim follows.

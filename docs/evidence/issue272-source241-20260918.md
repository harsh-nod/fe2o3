## Implemented Contract

An optional recorder borrows the existing authenticated collected closure
before the single production transaction consumes it. It is a private child of
the collector, not a second collector or a public collection accessor. The
existing two-argument transaction helper remains a no-recorder wrapper.

The report records canonical function/definition/instance identities, target,
compiler-assigned roles, exact driver arguments, working directory, extraction
mode/version and a fresh caller-supplied correlation ID. Definition and identifier
anchors, expansion and callsite anchors, normalized and original byte offsets
remain separate. Original bytes must match rustc's recorded source hash before
their SHA-256 is reported. The source hash algorithm is recorded too.

Rustc's definition anchor covers the signature, not the whole body. A generated
entry identifier that does not match a physical source token stays unavailable;
logical names are not substituted. Ordinary raw identifiers are tested against
their exact original bytes. BOM removal, CRLF normalization, UTF-8 boundaries,
imported source metadata and nonzero source-map offsets are covered.

The request, function/file counts, source reads, macro ancestry, diagnostic text
and encoded JSON are bounded. Nonregular source inputs reject without blocking
on a FIFO. Existing report paths are never overwritten. Aliases of explicit
extraction outputs and the wrapper binding sidecar disable recording, including
protected output symlinks. Failed serialization/writes do not leave a parseable
partial report. Fatal rustc errors are observed and re-raised, preserving failure.

See [the report contract](../tutorial-kernel-pairs-v1.md#live-compiler-source-census)
for environment variables, limits and exact claim boundaries. The report's
`diagnosticOnly` is true; `qualified` and `authenticatesCompilerExecution` are
false. A nonce correlates a request; it does not authenticate execution.

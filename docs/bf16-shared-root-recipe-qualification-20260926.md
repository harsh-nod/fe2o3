# Shared ordinary root preparation — 2026-09-26

The complete ordinary root-recipe preparation is now shared separately from
verification. The ordinary path immediately verifies the unverified prepared
recipe. This is a prerequisite for a strict nominal adapter, not that adapter
or nominal normal-compilation admission. Broad accepted exits remain 6/18.

## Preserved behavior

Preparation retains the original root/launch checks, input reads, conditional
writes, guards, bounds/access matching, effect order, CFG expansion, source
rows, reference expressions, and complete kernel construction. Its continuation
keeps preparation scratch alive through ordinary verification. Singleton,
borrow and induction scopes retain their nesting; the explicit helper-expression
drop still precedes its manual credit release in non-test verification.

The private prepared assertion mask is bound to the exact function and type
slice. Its Vec allocation moves rather than being cloned. The original first
block-count refusal, analysis point, authenticated induction OR, guarded
progress checks and graph-constant contradiction behavior are retained.
It does not accept caller-authored Boolean proof masks or treat BoundsCheck
decisions as memory-access certificates.

Root and an independent reviewer reconstructed the old parent byte-for-byte
after reversing the extraction, CFG split and includes. Preparation moved
17,741 bytes verbatim; the 35,319-byte CFG tail remained verbatim. The
verification tail matched after whitespace normalization outside strings.
This source audit is not an independent semantic proof.

## What remains

The shared ordinary core still uses legacy resource preparation. Its generic
private continuation is not an escape-proof or original-ledger nominal
constructor. A strict path must consume source-bound rich tables and complete
retained Final effects, charge all new allocations/work/frames, preserve
conditional writes and reference expressions, and record the actual tensor
position after CFG expansion. Source block numbers are not ranked coordinates.

NominalPending, ordinary source construction and ranked/attachment guards remain
unchanged. Full nominal root preparation, correspondence, checked attachment,
formal-memory and LLVM continuation remain pending. No GPU or native LLVM
execution, physical debugger capture, runtime-condition discharge, source
custody export or protected artifact/launch authority is established here.

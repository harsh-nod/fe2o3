# Original fixed-proof constructor retention qualification — 2026-09-27

A new test-only original-constructor component retains partial and completed
proof storage through source/resource postflight. It is a prerequisite for an
independent original fixed-query oracle, not a new production compilation route.

## Implementation

Four new cfg(test)-reachable leaves and three additive registrations preserve
the original production constructor. The component captures the original ledger
before creating its one exclusive strict handle. It preserves original
fixed-frame admission, work charge, source identity, evaluator-frame admission,
proof construction, checked-index allocation and both cache-constructor order.

Persistent checked-row vectors and caches are attached to an outer owner before
the next fallible checkpoint. The retired payload is installed before return,
error or resumption of the same panic Box. It contains no source/resource loan.
The owned payload survives source/resource postflight, then is destroyed before
refund to the original Budget and owned counter. An occupied retirement slot
refuses without overwriting another payload; a second prepare is terminal.

Expected constructor behavior comes from the original implementation and an
independent copy of its positive-debit sequence, never from the candidate lazy
owner. Root verified seven full original inverses (32 ordered operations,
37 replacements), three complete registration inverses and 56 source spans.
Formatting was retained separately from the frozen source proposal.

The new observation prefix has 38 main and 12 nested typed frame rows plus
unchanged cache-retirement terms. Original-versus-retained component runs pay
the same declared prefix before comparing the original debit suffix. They use
separate component budgets across comparison runs; within each run the actual
rich callback, original Budget and owned counter remain the same. These logical
charges are not a claim about complete allocator capacity, stack or RSS.

## Remaining boundary

These controls exercise constructor retention with empty query caches, not
original query execution or genuine nonempty proof comparison. The borrowed
constructor path does not exercise every owned side arm. Checkpoint panics do
not claim arbitrary meter unwind or deterministic allocator-overcapacity tests.
Bounded row snapshots expose completeness rather than claiming truncated data
is a complete proof.

Next increments are the original query driver, exact nonempty cache/checked-row
content and allocation-preservation controls, then sequential original/candidate
comparison under the same authentic source and Budget with explicit error,
panic and denial cleanup. Option-first prelude, later writers, joint bounds
driver, mandatory verification and production routing remain separate work.

No debugger activation, public capture gate or global compiler pin change.
Accepted broad exits remain **M1/V1/V2/U1/U2/U3 (6/18)**.

# Actual-source local-order feasibility

This private, test-only experiment connects ordinary Rust source to the
existing checked local-order service. It is not a persistent recipe API,
public continuation or completion of U3. The fixed production policy and
source admission are unchanged.

## Exact checked boundary

The selected initializer is `(a ^ b) & (c | d)`: one first, plain immutable
binding with four distinct immutable `u32` formal parameters. The fixture is
a direct nongeneric kernel root with a checked output store, authenticated
gfx942:xnack-/wave64 and required **and** maximum workgroup size 64x1x1.
Aliases, ambiguous selections, expanded or offset-normalized source, changed
operators, duplicate inputs and other target/launch profiles are refused.

The actual callback retains typed HIR identities and original/normalized
ranges, then follows ordinary import, middle end, SSA, materialization,
ranked checks and target-neutral attachment. It joins all five function
identity axes, parameter ordinals 1-4, exact operator attribution and
semantic/KIR values. The connected owner is a genuine live V12 graph with
pointer-identical correspondence storage, not relabeled V8 diagnostic bytes.
The existing target binder produces a fresh V12 owner over that same graph.

A retained file descriptor binds the exact file bytes; semantic authority
remains with the live compiler witness and owner. Parsed-source/hash/range
checks reject stale bytes and normalization. File currentness is rechecked
before reporting. This does not claim that rustc read through that descriptor
or that one file hash authenticates every compilation dependency.

The existing `schedule_checked_u32_local_order_v1` service receives the exact
three-operation region. `SourceOrder` retains the target-bound bytes;
`ReverseReady` swaps the two independent first operations while preserving
the dependent final AND. A repeated ReverseReady invocation must have exactly
the same bytes. All three transformations independently replay their checked
transition. A one-operation malformed region must refuse with `RegionBounds`
and restore the storage floor.

## Observed qualification

The September 19 mi350-2 working-tree run
`phase11-local-order-source-r1/observation.json` is 53,334 bytes, SHA-256
`b8b216edad7c0292c203d78eb7932b74bc4b92b4ba07e617c7af44b3dd3995d3`.
The selected unit gate and the separately selected actual-source ladder pass.
The ladder has 11 actual callbacks:

- Original positive, exact fresh-process repeat, and a renamed-parameter
  positive with a UTF-8 comment shifting the initializer range.
- Eight exact refusals: ambiguous initializer, local alias, changed operator,
  duplicate input, gfx950 target, required/max128 launch, BOM normalization
  and source changed after retention but before parsing.

Each positive observes SourceOrder result IDs `[14,15,16]` and ReverseReady
`[15,14,16]`. The renamed case freshly joins its new source range/identities;
it does not reuse old attribution. The first and repeated positive reports
match exactly. The original initializer is at bytes 231-248; the renamed one
is at 295-320, with original and normalized offsets equal in both.

The existing V12 simulator executes both complete scheduled kernels, not
only the selected expression. Five scalar vectors, output lengths 0/1/65,
two replays and two orders produce 60 runs per positive, 180 total. The
independent host oracle is `(a ^ b) & (c | d)`. All output and initializedness
checks, surrounding canaries and immutable-input checks pass; the report
records no incomplete race/conflict assessments for these runs. This finite
simulation is not a universal equivalence proof or hardware observation.

The unit and source gates retain unchanged Rust/Cargo/crate-README inputs:
3,703 files, 73,029,965 bytes, census SHA-256
`016fce3805859c111ec51f663ec8c6fd007d7a925c5b84fa6039ed6581700b0c`.
This documentation is outside that census. Results are working-tree test
evidence, not release or closure attestation. The initial unit attempt failed
because a shared Cargo target reused another worktree's older dependency;
the package-scoped rebuild corrected that setup without changing source.

## Bounds and reproduction

Source input is capped at 64 KiB. Own source scans have a cumulative
1,048,576-unit work and 512 KiB storage envelope, with a 4,096-row bound.
Retained-file operations separately charge a 32 MiB work/16 MiB storage
envelope. Compiler queries and the inherited target-binding allocation
domain are not presented as fully covered by those local scan ledgers.

Target-owner admission, the malformed refusal, all three schedules and their
transition replays share one 20,000,000-unit work/32 MiB storage budget.
The positive observed 115,503 work units and a 134,710-byte peak; the renamed
positive observed 115,414 units at the same peak. Retained outputs are charged
together. Both orders share one oracle ledger capped at 60 runs, 8,000,000
steps and 2 MiB prepaid host payload; each positive observed 73,000 steps and
171,908 prepaid bytes. Each simulation has its own bounded engine limits.

The harness retains ten files/3,865 bytes under a ten-file/655,360-byte
source-copy cap. Fresh source lives under ignored
`target/source-bitselect-candidate-roundtrip/<output-basename>` while provider
authentication retains repository cwd. Containers must be real, nonsymlinked
and fresh. This source inventory is separate from `CARGO_TARGET_DIR` and
dependency/compiler outputs. The task runner separately bounds subprocesses,
streams and combined cache/callback storage.

From the repository root with the pinned toolchain/provider closure and
normal bounded build settings:

```sh
cargo test --offline --locked -p rustc-codegen-fe2o3 --lib \
  source_local_order -- --nocapture

FE2O3_TEST_SOURCE_LOCAL_ORDER_OUTPUT=/absolute/new/local-order-run \
  cargo test --offline --locked -p rustc-codegen-fe2o3 --lib \
  production_rustc_driver_v1::source_bitselect_feasibility_v1_tests::roundtrip::local_order::actual_source_local_order_feasibility_ladder \
  -- --exact --ignored --nocapture
```

Use a new absolute task-owned output and a bounded safe basename. The actual
ladder is ignored by default and must be explicitly selected. Divergent
worktrees must not silently reuse stale shared-target dependency artifacts.

## What remains outside this experiment

The report explicitly sets `persistent_recipe_admitted`,
`fixed_production_policy_modified`, `final_source_output_admitted`,
`native_emitted`, `hardware_observed` and
`grants_artifact_or_launch_authority` to false. Scheduled diagnostic outputs
are not final production output; earlier ranked checks are not relabeled as
proof of a resumed compilation.

Persistent recipe ownership, source-anchor replay/rebind after edits,
invalidation of dependent evidence, version/target custody and the owning
fixed-policy continuation still require the joint schedule/compiler contract.
No schema, public policy ID, arbitrary pass-choice engine or detached receipt
admission is introduced. Applicable final native/resource checks and a public
author workflow remain future work.

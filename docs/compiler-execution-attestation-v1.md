# Compiler Execution Attestation Protocol V1

## Status

This document fixes the authority-free wire protocol used by the next
protected-issuer milestone in
[issue #218](https://github.com/harsh-nod/fe2o3/issues/218). The authoritative
codec is in `fe2o3-runtime-protocol`.

The protocol authenticates an Ed25519 signing key selected by a caller-pinned
policy. It does not yet authenticate protected compiler execution. A
[protected issuer admission](compiler-execution-issuer-admission-v1.md) now
retains the hardened service process, exact static executable, private service
channel, and sealed policy-matched key, but deliberately exposes no signing
operation. No freshness state machine, supervised compiler occurrence,
durable replay ledger, receipt carriage, or Worker V3 authority join exists at
this checkpoint.

## Records

### Issuer policy

The 184-byte policy pins one exact issuer executable, its complete runtime
closure, one Ed25519 verifying key, one policy generation, and the only
supported compiler-execution subject version.

| Offset | Bytes | Field |
|---:|---:|---|
| 0 | 24 | Header: `F2O3CEP1`, V1, zero flags, length, zero reserved |
| 24 | 8 | Nonzero policy generation |
| 32 | 40 | Issuer executable SHA-256 and byte length |
| 72 | 40 | Issuer runtime-closure SHA-256 and byte length |
| 112 | 32 | Non-weak Ed25519 verifying key |
| 144 | 2 | Supported subject version `1` |
| 146 | 6 | Zero reserved bytes |
| 152 | 32 | Domain-separated policy identity |

### Challenge

The 200-byte challenge is generated by the protected issuer for one exact
policy, subject, nonce, and rollback-ledger position.

| Offset | Bytes | Field |
|---:|---:|---|
| 0 | 24 | Header: `F2O3CEC1`, V1, zero flags, length, zero reserved |
| 24 | 32 | Policy identity |
| 56 | 40 | Compiler-execution subject SHA-256 and length |
| 96 | 32 | Nonzero issuer nonce |
| 128 | 8 | Nonzero rollback sequence |
| 136 | 32 | Prior rollback anchor |
| 168 | 32 | Domain-separated challenge identity |

Sequence one requires an all-zero prior anchor. Every later sequence requires
a nonzero prior anchor. A public codec constructor does not make a
caller-created challenge fresh or issuer-owned.

### Request

The 946-byte request prevents a compact subject binding from replacing the
actual canonical subject at the issuer boundary.

| Offset | Bytes | Field |
|---:|---:|---|
| 0 | 24 | Header: `F2O3CEQ1`, V1, zero flags, length, zero reserved |
| 24 | 200 | Complete canonical challenge |
| 224 | 690 | Complete canonical compiler-execution subject |
| 914 | 32 | Domain-separated request identity |

Construction and decoding independently require the challenge's compact
subject binding to match the complete nested subject.

### Receipt

The 400-byte receipt signs every semantic field through a domain-separated
digest of its 304-byte prefix. Its terminal identity also commits the 64-byte
signature.

| Offset | Bytes | Field |
|---:|---:|---|
| 0 | 24 | Header: `F2O3CER1`, V1, zero flags, length, zero reserved |
| 24 | 40 | Request identity and exact request length |
| 64 | 32 | Policy identity |
| 96 | 40 | Subject identity and length |
| 136 | 32 | Challenge identity |
| 168 | 32 | Challenge nonce |
| 200 | 8 | Rollback sequence |
| 208 | 32 | Prior rollback anchor |
| 240 | 32 | Derived next rollback anchor |
| 272 | 32 | Policy-pinned verifying key |
| 304 | 64 | Ed25519 signature over the domain-separated prefix digest |
| 368 | 32 | Domain-separated receipt identity |

The next rollback anchor commits the sequence, prior anchor, request, subject,
nonce, and policy. Receipt decoding validates the canonical schema, rollback
transition, non-weak key, signature, and terminal identity. Verification first
authenticates the signature and then compares every field with the caller's
exact policy, request, and current rollback anchor.

## Protected Issuer Contract

The production service must add properties that the codec intentionally
cannot provide. Admission now implements the process/executable/runtime/key
preconditions in items 1 and 2; completing either item still requires every
signing transition to revalidate that retained admission:

1. Admit only the caller-pinned issuer executable and runtime closure.
2. Own the signing key without exposing it to Cargo, rustc, the backend, or
   the runtime verifier.
3. Generate the nonce from the protected freshness source.
4. Observe the exact supervised rustc/backend occurrence and independently
   reconstruct its canonical subject.
5. Accept one bounded request over the existing descriptor channel without a
   shell, COMGR, or command-line compiler/linker path.
6. Compare the request with live occurrence custody and the outstanding
   challenge before signing.
7. Durably commit the next sequence and rollback anchor before releasing the
   receipt; a crash may consume a sequence but must never reuse one.
8. Bound time, input, output, descriptors, memory, and child-process cleanup.

The runtime verifier must independently pin the policy, reconstruct the
subject from strict Worker V3 custody, verify the signature, atomically compare
and advance its own durable rollback state, and consume the result in the
sealed authority join. A pure call to `verify` is repeatable and therefore is
not replay exclusion.

## Authority Boundary

Policies, challenges, requests, and receipts are cloneable inert evidence. The
protocol-level verified result is move-only, but it proves only that an exact
receipt was signed by the policy-pinned key and matches the supplied rollback
input. Its API explicitly reports false for protected execution, compiler
authority, load authority, and launch authority.

Only the future protected issuer can establish supervised execution. Only the
future durable Worker V3 verifier join can promote that fact into compiler
authority. No wire value can be deserialized directly into authority.

## Test Requirements

The protocol suite must retain:

- exact size and canonical round-trip checks for all four records;
- exhaustive one-byte mutation rejection across all 1,730 wire positions;
- independently encoded subject and compiler-closure fixtures;
- independently resealed invalid header, rollback, subject, and signature
  cases;
- policy, key, subject, challenge, request, sequence, and rollback
  substitutions;
- multi-step rollback-chain and replay rejection checks; and
- compile-fail coverage proving the verified result is move-only.

These tests qualify only the codec and pinned-key signature boundary. The
[protected issuer admission](compiler-execution-issuer-admission-v1.md) and
[durable issuer state](compiler-execution-issuer-durable-v1.md) now implement
the local protected signer foundation. Supervised compiler transport, Worker V3
carriage and verification, and MI300X end-to-end tests remain separate required
milestones.

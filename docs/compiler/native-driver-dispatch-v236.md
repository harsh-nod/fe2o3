# Native Driver Dispatch

The backend consumes its original loader-owned policy/service copies once before
production collection. A sealed fixed-size header selects either the V1 or V3
nominal constructor. Both records are 216 bytes; length never selects the family.
Unknown/V2 magic, invalid header fields, malformed selected policy bodies, resource
exhaustion, and service refusal are terminal. No second constructor, raw-slot
recapture, account replacement, or legacy fallback follows refusal.

The selector is inert. Its shared descriptor checks require the existing exact
mode, seals, CLOEXEC, length and held-object identity; the matching full constructor
still validates the complete record. The selector uses the existing native policy
I/O work/storage envelope, with fixed positional I/O and no allocation or new FD.

The selected move-only owner retains the original TARGET budget through collection
and publication. V1 enters the existing V3 handoff; native V3 enters the existing
conditional V5 handoff and signed receipt protocol. Error/drop closes retained
service/input custody without restoring consumed work or replacing the account.
SOURCE retains its independently established original account.

This is driver connectivity, not a default-selection or authority change. Native
publication still requires original Direct roots, RawEmpty helper policy, actual
source/F checking, original runtime/issuer custody and all existing publication
joins. Unsupported programs refuse rather than use another family. Packaging,
service readiness, and this dispatch's unit tests do not establish compiler,
proof, artifact-load, or GPU execution qualification.

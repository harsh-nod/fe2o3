# Mixed Compiler Default Activation

The mixed compiler is not yet the sole default pipeline. The source-owned
continuations and their independently checked graphs are real production APIs,
but neither copied observations nor successful optimization authorize a Worker
request or an artifact. This checklist describes the remaining consuming joins;
it does not mark them completed merely because their components exist.

## Current Integration

`production_pipeline.rs` still selects the Current semantic importer in its
default target route. Its ranked/conditional/formal checks and publication
continuation are not the nominal V35 mixed pipeline.

The explicit source-owned pipeline now has this motion ingress:

```text
collector-authenticated Rust closure and compiler bindings
  -> fixed nominal V35 import
  -> original semantic SSA and complete ABI/target/launch custody
  -> fixed Policy10: integer worklist, local CSE, dominance CSE, DCE
  -> actual checked V18 LICM, using captured source layout limits
  -> source-owned relocation + complete definition/use/edge projection
  -> independently rebuilt input/output MemorySSA
  -> lexical consumer of the actual relocation owner
```

`with_original_source_mixed_licm_v28` retains the original compiler bindings
and both actual canonical endpoints through that lexical consumer. It settles
the relocation before the borrowed Policy10 prefix on success, selected refusal
and raw unwind. The returned observation is not executable output. The method
does not select a second default, retry another policy, emit relocated target
text, or convert the prefix witness into a motion proof.

## Required Joins

1. **One fixed front end and optimizer route.** The sole default must select the
   admitted nominal import and fixed mixed policy before lowering. Supported
   source forms must be handled generally; unsupported forms must refuse with
   the original typed failure, not fall back to a historical compiler path.
2. **Final relocation completion.** After motion, original source instances,
   memory effects, call/occurrence identities, private lifetimes, scalar values,
   bounds and runtime slice conditions must join the final graph. Replaying an
   operation map and MemorySSA is necessary but does not alone discharge those
   original-source and native obligations.
3. **Actual target continuation.** Target lowering must consume the final
   source/native-complete owner with its exact source, target and launch roster.
   Existing Policy10 target text concerns the pre-motion endpoint; it cannot be
   relabeled as relocated output or reconstructed from an observation digest.
4. **Refinement scope.** The current conditional CFG-model proofs use shared
   operator interpretations. A signed model result is not by itself a proof of
   MIR lowering, concrete memory/call semantics or the final moved program.
   Source-to-input and input-to-final refinement require their own exact,
   versioned producers and retained endpoint joins. LLVM remains a separate
   downstream trust boundary.
5. **Descriptor and execution custody.** Generated V3 descriptors must bind every
   original ABI field, final occurrence, target and layout. Protected compiler
   execution, its signed subject and the versioned Worker/finalizer replay must
   consume those exact producers. Equal bytes or matching hashes do not replace
   their ownership and provenance.
6. **Concrete runtime conditions.** The KFD/runtime path must discharge the
   retained launch, bounds, alias, access and initializedness conditions against
   the actual arguments. A physical invocation envelope is not a proof that an
   arbitrary source-static launch equation holds.
7. **Default switch and qualification.** Only after these joins exist should the
   default entrypoint consume them without an alternate-policy fallback. Test
   the complete current tutorial inventory, both admitted target profiles,
   refusal/cleanup paths, deterministic IR, and the real publication/runtime
   boundary. Historical tests can retain nominal old policy owners; shipping
   compilation must not silently choose them after a new-path failure.

The inert mixed Worker-input type currently records four open gates explicitly:
signed V18 source refinement, protected compiler execution, versioned Worker
and finalizer replay, and concrete runtime-premise discharge. None is cleared by
this backend motion ingress.

## Qualification

The new actual-source parent compiles two safe Rust kernels per program through
the existing rustc harness on both target lanes. A dynamic loop admits zero
iterations and contains live invariant bitwise expressions and a real Store;
the companion program is straight-line. It checks the final independently
replayed pair's actual input/output objects, complete original ABI and root
rosters, selected error/panic propagation and refusal before callback entry.

These are test obligations, not an assertion that the tests or a proof runtime
have passed. Root integration owns execution and records qualification results.

# Source-bound bounds components — 2026-09-26

This checkpoint supplies private compiler components for source scanning, extent
tracking and fixed-array guard authentication. It does not admit a complete
nominal-helper kernel or add a public authoring command. Accepted broad exits
remain **M1/V1/V2/U1/U2/U3 (6/18)**.

## Implemented components

The source scanner retains definition coordinates, definition counts, predecessor
rows, local values and slice extents. Ordinary compilation and the prepared
component share the original scan decisions. Duplicate-definition saturation,
call-result clearing, successor order and first errors are preserved. A completed
owner can answer source-coordinate queries without allocating replacement tables.

Extent preparation shares the original bounded traversal with the ordinary
compiler. Its prepared state retains caller-supplied argument slots and the next
argument counter; it does not assume an empty argument roster. Queries verify the
same source, type loan, rich tables and original resource ledger. Nonempty
operand projections are charged before the original transparency scan. Constant,
cast-refusal and 64-link traversal behavior remain unchanged.

The eager fixed-guard session accepts a private source/CFG loan and the original
resource adapter. Each query selects a BoundsCheck Assert by its actual source
block; callers cannot substitute a detached condition, index, extent or target.
The session borrows the original rich tables and retains its proof/cache storage.
Equal-content foreign function, type or graph loans, foreign ledgers and foreign
rich row loans refuse. A failed query makes the session non-reusable.

Guard authentication preserves the original exact unsigned index < nonzero
literal-extent comparison, definition stability, dominance, address-escape
checks and error order. Long projections and deep operand equality are prepaid
only on the strict route. The existing unique-success-predecessor and
success-not-entry checks still execute after helper authentication in the outer
bounds collector; helper success alone does not establish a complete safe access.

## Accounting and failure behavior

The source scanner admits explicit scan, value-initialization and borrowed-query
frames before the corresponding source-sized work. Its standalone query envelope
is retained once; extent preparation separately pays a conservative duplicate.
Checked formulas include nested iterators and call/result transfers. These are
logical reservations, not measurements of optimized stack size or process RSS.

Fixed-guard preparation adds an explicit 17-vertex helper frame inventory to the
existing assertion evaluator inventory. Partial construction retains accepted
credits; physical owners must be dropped before the enclosing owner refunds
those credits. The new tests assert successful cleanup instead of ignoring
release results. No peak allowance or existing capability profile was relaxed.

## What incorrect behavior is checked

The component controls detect substituted source coordinates, changed or foreign
loans, duplicate/late/escaped definitions, swapped comparison operands, mismatched
bounds messages, invalid literal widths, undercharged projection/equality work,
one-short work/storage budgets, retry after refusal and incorrect cleanup.
Frozen original helpers provide independent decision and logical-work oracles.

These are compiler preparation checks, not a general proof of memory safety,
race freedom, GPU ordering or arbitrary assembly semantics. Raw hostile test
fixtures are not admitted source evidence. Actual rich-table tests are identified
separately from those malformed fixtures.

## Required continuation

The actual argument producer remains unfinished. Ordinary comparison, induction,
switch and pipeline preparation can mutate argument slots, value IDs and emitted
operations before extent counting. In particular, an unsuccessful right operand
can leave valid left-operand mutations. A real bounds factory must preserve that
entire source-ordered state under one owner; synthetic empty slots or a constant
starting counter cannot replace it.

The fixed-guard session is intentionally eager. The final collector requires the
original lazy first-fixed-guard event and shared custody of source-scan, extent,
proof and operation storage under the same original resource handle. Those
lifetimes and their actual peak still need qualification.

Actual-source factory integration, independent full-source comparison, completed
operation streams, source-to-ranked correspondence, mandatory verification and
normal LLVM continuation remain open. No raw intermediate resume authority,
ready token, target dispatch or new physical debugger capture is granted.

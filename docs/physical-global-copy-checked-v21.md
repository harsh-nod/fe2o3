[physical-global-copy-source-v21.md](physical-global-copy-source-v21.md) remains

The separate [normal inert handoff](physical-global-copy-inert-handoff-v21.md)

Host/protected/native admission is not provided by either endpoint.

The move-only `ProductionPhysicalGlobalCopyCheckedKirOwnerV21` consumes the

## What is checked and what remains conditional

The typed memory derivation reads the actual immutable graph. It records:

- Four actual eight-byte kernarg reads, logical pointer/length roles at offsets
  0/8/16/24, exact source occurrences and the actual LGKM readiness boundary.
- One full-EXEC global input read and its original opaque result, immediate VM
  wait, exact address/index/EXEC SSA identities and source occurrence.
- One output store of that same ready result, the actual output-length
  comparison/mask, and the following store wait and saved-EXEC restore.
- Exactly two real logical allocations: readonly input0 and read/write output1,
  with actual Read/Write operation coordinates, width/alignment4 and affine
  byte offset `4 * global_id`.

For the retained source launch envelope128, both ordinary bounds obligations
remain512 bytes. The input read is unconditional and needs the full readable,
initialized prefix even when output length is zero. The output bound remains
conservative; the authored guard does not shrink its formal LaunchEnvelope.

The global report retains the input/output alias requirement rather than
assuming distinct logical arguments are distinct runtime allocations. Input
readability and initialization, output writability, required bounds, valid
shared/owned source borrowing and non-overlap still require authentic runtime
bindings. A readonly input view is not evidence of a real live allocation.

The compiler-owned kernarg prefix is separately required to be32 bytes,
alignment8, live/readable/immutable through execution and disjoint from output
writes. It is not a third user allocation or a ghost source parameter.
Consuming only the report's global-access portion is not complete admission.

The ranked projection uses a conditional128-element readable input prefix,
not a claim that the actual dynamic input length is128. It does not invent an
input-length guard. The output guard remains derived from the actual authored
comparison and output length. Loaded data is opaque `IndexUnknown`, never a
deterministic function of its address or an invented constant. Dependency rows
retain original SSA inputs, but this projection is memory-safety analysis, not
functional correctness or native instruction certification.

Conditional alias classes and finite views are justified only under the
retained unresolved report. The existing fixed mandatory analysis session
runs; clean reports do not discharge those conditions. Exact replay compares
the source/KIR relation, every memory-report field, the ranked graph/text and
middle-end evidence. Generic formal extraction still reports these physical
operations as unmodeled.

## Resource and authority boundaries

The same canonical work meter remains cumulative, including refusals. Added
report, temporary analysis, recipe/text/evidence storage use bounded logical
reservations with restoration of the caller's incoming floor. The existing
semantic SSA and PLIRON session retain their own independently bounded
accounts. This is not whole-compiler heap, allocator or RSS measurement.

The public checked boundary retains the full report-bearing ranked error
inline. Helpers use a smaller allocation-free exhaustive error carrier; no
boxing, diagnostic truncation or lint suppression is used to conceal the
large public error payload.

No ABI conditions are marked satisfied; no protected publication, finalizer,
host binding, native or GPU authority is returned. No wire versions or opcode
tags change. KIR20 and existing ordinary compilation routes remain unchanged.
This bounded global-read/wait slice does not complete the broader M3 memory,
barrier, LDS, atomic, convergence or hardware exits.

Component tests distinguish inert graphs from actual Rust custody. The separate
normal-driver ladder exercises source to this checked owner and inert handoff;
its authored controls require actual root-run qualification, not inference from
structural tests. Native and host qualification remain separate.

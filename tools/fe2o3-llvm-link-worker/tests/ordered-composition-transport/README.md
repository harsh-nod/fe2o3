# Private typed composition transport checker, increments 1+2 plus finite caller DATA

This is a test-only extension of the existing gfx942 MC analyzer. It is not a new public wire, compiler refinement owner, native interpreter, protected-artifact route or execution permission.

The normal worker does not define FE2O3_PRIVATE_COMPOSITION_TRANSPORT_V1. In that build all new hooks disappear. A separate private test translation unit includes the same analyzer with the definition enabled. The old effect/trace/ELF/loader/return/call-closure/aggregate-budget checks remain mandatory. A fixed internal observer borrows const references to the actual MC tables, decoded MCInsts and existing CFG; it accepts no callback or caller-selected instruction rules. No borrowed MC object escapes.

## Exact partial claims

- ConditionalHelperO0: ordinary C ABI inputs on actual v0/v1/v2, for entry EXEC domain E only, reach authored v10/v11/v12; the XOR/AND or MoveInput2 result passes through actual a0 into returned v0. The O0 caller, lane spills, address calculation, runtime safety and full source-call ABI transport are NOT covered.
- CallerToHelperO0 (new, separately selected): actual O0 descriptor enable order labels symbolic kernarg s4/s5; exact tied lane1/2 spill/reload, seven pending load words, lgkm0, one exact EXEC save/restore and three scalar-to-vector moves derive v0/v1/v2 at the sole decoded direct call. The actual target file offset and s30/s31 return pair join the complete existing helper DATA relation. The post-call caller, AGPR-result-to-store chain, address, predicate, runtime memory validity and full ABI/functional equivalence remain unproved.
- InlineRootO3: actual descriptor/metadata selects the s0/s1 kernarg base; one exact eight-word load remains pending until lgkm0. Actual source ABI offsets16/20/24 label the three scalar arguments. The result reaches store DATA under the one actual E-intersect-P mask. The guard's truth and the store ADDRESS are NOT proved. Readability/initialization and every runtime memory condition remain unresolved.

These checks are deliberately closed over the observed 10/9-row helpers and19/18-row roots, their exact architectural operand roles, CFG and machine encodings. The new profile additionally checks the actual 45-row entry prefix of the closed 144-row/7-block/840-byte caller; there is no prefix backedge or second static call. All remaining caller instructions retain the original analyzer's checks but do not receive new DATA semantics. They do not silently generalize to other compiler output. Whole32 membership, tuple decomposition and alias kills use the actual register classes/units. AGPR0 and VGPR0 are distinct. The private code never asks for a printed register/opcode name.

Opcode IDs and operand-class IDs are joined to the root-measured exact f58b06d LLVM tables, real metadata and independent literal instruction encodings. They are not portable numeric identities for another toolchain.

The SourceProjection input is INERT. Its42/41-row grammar preserves exact positional SSA joins but cannot reconstruct the live Rust owner. The separate fixed observers bind the completed retained source-role report and its publication/canonical/normal-LLVM/worker/handoff/descriptor bytes, then run the unchanged ordinary worker and independent metadata/interval controls. These new static worker runs do not rerun the historical frontend provider. Passing a fabricated projection to this low-level test-only API never supplies source custody.

## Ownership, accounting and failure

The caller's Account outlives every Result. Before any retained checker state, one move-only Reservation prepays65,536 logical storage bytes and280,576 work units. It preserves incoming floor/peak/work/denials, checks subtraction before addition, never refunds work and releases storage once. A successful Result retains the conservative full reservation through output consumption even after the temporary workspace is destroyed. The account is not LLVM allocation accounting or process RSS.

The callback has no heap state, external invocation or resettable ledger. Its compact refusal is sticky. Source rows/symbols, register/unit caches, working state and eight snapshot slots are all fixed-size. The entire envelope has a compile-time size guard; no allowance raises it. Metadata readback borrows the existing parser's document: kernel maps≤64 entries, argument maps≤16, at most24 arguments. find(StringRef) constructs a non-copying temporary DocNode and std::map lookup; already-checked array indices cannot resize. It does not allocate a second document.

A selected per-function result is only pending. Commit happens after the old analyzer's final closure, acyclicity, trace/effect and entry-budget checks. Late refusal disposes pending state and returns no Result. No positive data is serialized by this checker. Non-native exceptions/termination cannot turn failure into success; ordinary LLVM errors stay in the existing analyzer's bounded diagnostic domain. Reservation denial itself is allocation-free.

# Fresh composition DATA-transport observer (test only)

This separate executable consumes an explicitly pinned, completed
`fe2o3-test-composition-transport-ladder-v1` report. It does not accept raw LLVM
as a standalone input, reconstruct a Rust owner, publish an artifact, or launch
a kernel. It reuses the existing promoted observer and ordinary LLVM/LLD worker
unchanged, then adds a conditional typed MC observation.

Exactly six root-run cases are intended: copy/preserve/edit at O0/O3. The new
`fe2o3-test-composition-transport-native-v1` observation is separate from the
unchanged `fe2o3-promoted-composition-native-observation-v1` baseline. Old
source/native reports and observer routes are not relabeled or modified.

## Joins and limits

The reader requires the fresh aggregate plus its byte-pinned embedded/retained
normal report. It joins the actual fresh source/invocation/publication snapshot,
normal/public LLVM, canonical bytes, source descriptor, worker extension,
handoff, standalone role rows, independent source CPU result and exact program.
The old reader retains its inode/stamp, package, provider, ABI, metadata and
source-preservation checks. Added inputs use a separate 32-pin closed roster;
the old 32-pin roster is unchanged.

The caller assigns borrowed symbol StringRefs after the returned input has
reached its final location, avoiding moved small-string references. Actual
source rows and identifiers remain observations, never source custody.

The worker receives unchanged normal LLVM. Its ordinary response/derivation,
artifact retention, metadata/resource and authored-interval controls all run
first. The new consumer then reads the same retained HSACO (<=1 MiB), checks its
digest, and runs the unchanged default analysis and typed analysis on the exact
same request. Their complete effect/trace bundles must be byte identical.
There is no second worker invocation, decoder, interpreter, external MC
callback or production acceptance change.

Each typed attempt prepays the existing 65,536-byte / 280,576-work transport
envelope, atop explicit floor 37/work 11. The success receipt remains alive
through JSON serialization and both bundle/output writes. Only afterward is
the receipt destroyed, exact floor restoration checked, and another attempt
required to fail for cumulative work. A separate terminal observation records
that order. A second independent account exercises an actual late original
global-write budget refusal; no pending typed Result may escape it. Two
simultaneously live accounts are intentional and separately bounded. These
logical accounts do not claim compiler/LLVM RSS or reset the original source
ledger. Existing parser/worker resources remain their established domain;
wrapper output is separately capped to two 1-MiB bundles and a 64-KiB JSON.

O0 proves only the selected helper DATA path conditional on the ordinary C
argument ABI and entry EXEC domain; the caller/lane spills remain unproved.
O3 covers the closed kernarg-load/wait/program-to-store DATA relation under the
observed opaque EXEC intersection, not address correctness, predicate truth,
memory initialization/alias conditions, runtime behavior or full equivalence.
SGPR/VGPR/AGPR names in reports are diagnostics, not admission authority.

## Qualification contract

The private runner's PROFILE.json is disabled until root freezes a separate
successor with exact completed source/build receipts, source census, observer
ELF and dependency pins. R1 records the historical 92514ff7 source report;
root may bind a fresh same-schema report after the merged-source qualification.
No runtime self-binding, command-line selection overrides or historical
receipt repinning is permitted.

The native child original-start deadline is 110 seconds. The root runner uses
120 seconds per child and 900 seconds overall, rechecking after close, parse,
hash, revalidation, fsync/publication and awaited stdout write. Each child
stream is capped at 3 MiB, all six at 16 MiB. The child writes only a
transport.pending.json observation. Any child/report file alone is not
acceptance; the completed root runner receipt is required. A late/failing
overall publication quarantines report.json. Cleanup proof is direct-child
exit/pipe closure only, not whole-family containment; an outer root supervisor
remains required.

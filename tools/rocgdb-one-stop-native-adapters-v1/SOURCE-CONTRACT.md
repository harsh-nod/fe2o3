## Exact successor, not source activation

source-manifest.json pins two selected-source stages: stopped-wave and
one-stop-disabled-r4. The former exactly joins the sibling stopped-wave
package's nineteen postimages and additional pinned unchanged upstream
contexts. The latter adds fifteen leaves, changes seven existing files, and
retains twenty-six contexts byte-identically. All thirty-three predecessor
files must exist; every newly introduced leaf must be absent at that stage.

The new source lives inside the existing AMD target translation unit. Its
activation header remains a constant false return and compile-time assertion.
No permissive build flag, request schema, public token or profile override is
provided. R4 retains the API-compile correction and the actual signed internal
breakpoint presentation correction; the later enabled R5 source is excluded.

## Actual source-owned native sequence

The adapter has one noncopyable owner in the existing client. Selection would
require the actual inferior registry, process/program-space, PID/start and
retained thread identities, but the packaged gate refuses before selecting.
JSON rows describe observed state and never reconstruct an owner.

The source retains the 776-byte checkpoint, separately pinned original
5,312-byte ELF and 12,288-byte mapped image, descriptor/entry/bias, trap
backing, ring slot/indices, kernarg and 272-byte logical output. The fixed
kernel is the qualified store-at-64, wait-at-72, trap-at-76, end-at-80 fixture.
The dispatch completion-address query joins signal BASE, not its atomic
value at BASE+8. Query results still need actual runtime joins; fixed hashes
are not attach, source custody, sampling exclusion or process-control proof.

The current native event wrapper remains the sole ACK owner. Its finish
returns the already obtained native status; no side client or second ACK is
introduced. Callback, wave-stop and code-object facts are joined before the
original ACK invalidates the native event handle. Unknown events/statuses
poison the sequence. No code treats an OS queue ID as a native queue handle.

The selected solib path replaces its ordinary code-object-list call rather
than draining a second client. Zero-output terminal-list allocation is a
scoped request, not a permissive null-allocation policy. Actual request sizes
are pre-debited, one known allocation is retained, and ambiguous/reentrant or
oversized requests refuse. Unselected paths retain their original delegates.

Generic target_resume and target_commit_resumed hooks precede target effects.
The exact infrun origin, scope, signal, native STOP/PC, actual thread and
not-executing/not-resumed state are required. Callback stepping is a separate
one-use path bound to its real thread/address space/inline address. Native
INVALID_WAVE_ID is checked before the old compatibility behavior can swallow
it. State claims from a controller do not satisfy these native predicates.

The private software breakpoint checks its real location and owner on reset
and presentation. It prints a signed negative internal breakpoint number,
requires the exact provisional host stop, and rejects recreation and resource
queries. Deletion records intent; only after breakpoint_auto_delete returns
can a chain/location census establish retirement. Normal MI stopped output
is complete before diagnostic emission; no provisional stop is made current
merely by printing a row.

The delete/consistent/empty-list/ACK/continuation/unload sequence and retained
exit observer run before registry reset. Lifecycle disappearance is not
normal MI exit, target completion, wait/reap, cgroup emptiness or family cleanup.
Those are distinct external observations and remain unqualified here.

## Finite accounting domains

The retained core/adapter caps are 65,536 logical storage bytes, 192 newly
introduced queries, 65,536 inferior read bytes in at most 256 calls, 131,072
logical work units, sixteen diagnostic rows, sixty-four event IDs, eight
callbacks and one bounded client output of at most 128 bytes. Fixed storage
charges sizeof(native_adapter)+4096+128 before the selected path. This does
not account all GDB/BFD/allocator/ROCdbgapi internal storage or prove latency.

The reviewed fixed-route estimate is 187 new queries, 47,904 inferior bytes
and a 101,376-unit checkpoint/hash/root-work subtotal. Actual extra work still
consumes the remaining original ledger and can refuse; these estimates are
not runtime measurements or guaranteed successful execution. There are no
resets, refunds or retries after an unknown read/native outcome.

The separate executable-file domain permits two exact 4,162,064-byte payload
passes plus two EOF requests (8,324,130 requested bytes), with 8,324,224 padded
SHA-work bytes. Proc requests have a separate 16,384-byte cap. These logical
domains do not claim to hash an entire queue ring or all allocation backing.

## Package controls and historical evidence

The external-tree placement tests adapt the root-corrected R3 definition
anchors, not the earlier forward-declaration-matching controls. Presentation
tests adapt the R4 real breakpoint overrides. Every mutation starts by
accepting the exact baseline in memory; source checking requires all selected
external files before these controls run. Package-input tests exercise exact
pins/rosters/stages, activation refusal, malformed bounds/UTF-8, absent inputs
and coordinated metadata mutation. The inert C++ fixture checks only the
constant gate and fixed locator grammar. No test invokes the native adapter.

The historical R4 build receipt and original placement predecessor receipt
are provenance only. Packaging neither reruns nor strengthens them. Fresh
package controls, full-source preparation, builds, dynamic startup closure,
controller ordering and any authorized native attempt all remain separate.

# Immutable disabled physical-v3 source contract

The canonical manifest digest is fixed in the read-only verifier. Unknown keys, stages, source rows, changed pins and coordinated metadata edits refuse. Parent physical-v2 source/manifest/patches/verifier are immutable; this is not an in-place update.

Both explicit stages select the same ordered 63-row union. The extended parent stage is 2,177,182 bytes and the new maintenance stage 2,183,132 bytes. The old 60-row final stage contributes 2,162,093 bytes. Three primary lifetime headers contribute 15,089 bytes: process-stratum-target.h (7,435), gdb_ref_ptr.h (5,508), and refcounted-object.h (2,146). Exactly four hook changes add 5,950. The new source-only maximum is 2,144*1,024=2,195,456 bytes. Final headroom is 12,324; overage against the unchanged old-v2 cap is 20,444. Per-file 512 KiB and metadata 64 KiB stay fixed.

Every external source row is read once through the same no-follow regular bounded reader with hash/size/strict-UTF8/EOF/growth/identity checks and ONE cumulative total. No parent external-tree pass or overlay budget reset occurs. Parent source-package metadata, patch and fixture integrity are separate existing bounded roles, not omitted external source context. The verifier checks all 60 inherited parent-final pins and literally false activation/capture/publication in both stages.

Ordinary preservation is explicit: ordinary-transforms.json contains exactly 16 changes over four standalone hooks. Forward and reverse checks must join published postimages to exact public-v2 preimages. The other 59 source rows, including target commit call sites, core, profile, false gates, runtime interfaces, capture/publication and output contexts, stay identical between the extended stages. Old v2 source verification must refuse new changed hooks as its own final stage.

The CPU fixture includes the exact extracted require/info/current_identity/thread_roster and maintenance/commit method bodies. helper-extraction.json specifies closed source slices, hashes and two include-name-only adaptations from the qualified private fixture. The actual external ref_ptr implementation and unchanged parent owner core are used. Node controls join these to selected source; the C++ harness supplies mock inferior/process/top target/thread/registry objects and mock close side effects, not a second policy implementation.

The hostile controls exercise identity, ownership, pushedness, stack/stratum, epoch, in-flight, runtime, roster, execution/pending and work-budget drift before and after effect. Positive cases retain one initial resume and unchanged rows/output across legitimate already-armed maintenance. Safe retirement checks stack-owned nonfinal releases; failure after stack removal demonstrates retained references until destruction. This does NOT prove actual GDB ABI/layout, real close/callback behavior, or thread/OS synchronization. The implementation relies on GDB’s serialized debugger control model; source pins are not a proof against arbitrary memory corruption.

A valid guard charges 128 plus one inferior and one host roster item (130); a successful pair costs 260. Initial retention plus two guards costs 292; first normal retirement adds 32. These consume the ORIGINAL shared 131,072 work meter. With the historical v2 source estimate 129,240, those added initial/retirement charges give 129,564 before pairs; five pairs give 130,864 while six exceed the cap by 52. This illustrative composition is not guaranteed iteration headroom, a whole-GDB CPU bound or permission to enlarge/reset a cap. A failed post-effect guard remains a refusal. Tests retain partial-debit/first-failure behavior.

Two strong-reference fields are included by sizeof(native_adapter); 256 additional scalar scratch bytes are explicitly reserved. The original 65,536-byte logical cap and all API/read/row/packet/deadline caps stay unchanged. Actual complete-GDB layout/static_assert qualification remains separate from mock tests. Exceptional retirement may deliberately retain references and delay target close until debugger destruction; only checked normal release is guaranteed nonfinal.

Source metadata/placement controls never create a child or mutate the external tree. This package provides no patch-application/build/installation/native-launch automation. A selected-source projection can support these checks without being a complete checkout; do not relabel it a built/loaded qualification. Actual executable, startup, loaded closure, controller/family/replay, fresh coordination, cleanup and a genuine hardware stop require separate reviewed evidence.

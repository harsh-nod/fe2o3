# Source and authority contract

The parent physical-v3 directory is immutable. The final source consists of its exact 63-row selected projection plus five existing-file replacements; 58 rows remain byte-identical. The patch changes no selection, snapshot-capture or publication availability function. The manifest fixes all four authority flags false.

The 34 reversible edits retain two explicit stages: 13 diagnostic edits over four leaves, then 21 loaded-maintenance edits over five leaves. This is not a claim that the earlier failed native attempt proved every hypothetical guard path. Diagnostic group 7 identified the existing full maintenance guard, not its individual conjunct. The private source successor permits only a prospective first-loaded-success ACK whose same original owner, inferior, host, process/base/top targets and strong references are authenticated. Original entry retirement and ACK update/flush order stay intact. The first subsequent callback permanently retires this maintenance epoch. No added resume credit, ACK, MI command, stop, capture or retry is created.

Target references remain owned and inert through teardown, including exceptional paths. A last-reference close may consequently occur later; this is not claimed observationally identical in arbitrary exceptional target-stack destruction. No raw pointer becomes an authority or replacement-owner permit. Exact runtime checks and effect counts are carried by the whole selected source and CPU helper extraction, not a prose shortcut.

## Resource accounting

The unchanged native policy retains 64 KiB logical storage, 131,072 work units, 192 API calls, 256 inferior read calls and all existing file/process/output/deadline bounds. New retained adapter fields participate in actual sizeof(native_adapter). The separate loaded_maintenance_scratch structure explicitly accounts for selected added/helper vertices. Its actual host/GDB layout must be measured after a full build; no guessed byte residual is accepted. Existing 256-byte entry-maintenance scratch is not reused. Work admission and state checks remain in the exact proposed implementation.

The public verifier reuses the canonical regular bounded source reader. It reads one selected 63-row external stage under the same cumulative 2,144 KiB accepted-payload bound; it does not open two independent external source budgets. Parent package verification and test metadata reads are separate fixed local work and are not represented as included in that accepted-source sum. The inherited reader provides stable named/open identity, nonblocking no-follow open and EOF checks; it is not a hard kernel/syscall-latency or OS-global proof. No native resource cap is raised.

## Extraction and publication

The main CPU fixture has only two include-name changes from the qualified private fixture. Actual helper bodies are extracted from selected final source. Its legacy runtime-ACK comparison body is derived by reversing the loaded edits to the exact diagnostic intermediate before the single function-name substitution. The unchanged source-owned binding body is independently pinned and joined by the public selected-source tests. The scratch body is an exact substring of the final native header.

The first-poison fixture changes only its old/current owner include paths. Its old owner is the immutable package-root source, its new owner is the selected final header. It preserves unknown-first-site behavior and original failure predicates; no later poison may overwrite the first failure/site.

Source placement and mocked controls do not establish GDB ABI, actual runtime acceptance, program output, successful stop/capture, or clean host state. Public verification is disabled and read-only. A private bound generation requires fresh actual products and the independent closed runtime qualification chain; this package grants none of it.
